VIVATLAS Clipper sends the page you are on to a VIVATLAS server, a self-hosted catalogue (source: https://github.com/bobpanil/VIVATLAS). It needs a server and an account, so here is the public VIVATLAS demo server, with a fixed test account for reviewers. Clips on it are cleared after 24 hours; the account stays.

Server: {server}
User: {email}
Password: {password}
(No two-step code on this account.)

How to test:
1. Click the toolbar button. Enter the server address above and press Continue.
2. Firefox asks to allow access to that address. Allow it. Firefox may close the popup while it asks; open it again and it carries on.
3. Type the user above into the Email field, and the password. (If you sign in on the server's website first, the clipper picks up that session and skips this step.)
4. Open any web page, click the toolbar button, and press Add to VIVATLAS. Open the server address in a tab (or use Open VIVATLAS in the clipper) to see the clip listed. The demo has no AI, so each clip becomes a plain card from the page's title and text. On the demo every clip stays private, even when Public is chosen; on a real server Public shares it.

Notes for the review:
- Plain JavaScript, HTML and CSS. No build step, bundler, minifier or remote code.
- Host access is optional and asked for only for the one server the user types in (optional_host_permissions). It is needed to call the server's API and to read that server's own session cookie, so a user already signed in on the website is signed in here too.
- activeTab and scripting read the readable text of the current tab, only when the user opens the clipper on it. The text, address and title go to the user's server only when they press Add to VIVATLAS.
- The email and password are sent only to that server's sign-in endpoint and are not stored. The extension keeps the session token in storage.local.
- No analytics, no third-party services.
